# GitHub Profile README Refresh Design

## Goal

Refresh the profile README so that verified public work from October 2025 onward
appears first, while preserving a concise record of earlier projects.

## Source and privacy boundaries

- Use 2025-10-01 as the inclusive activity cutoff.
- Base new claims on public GitHub repository READMEs and commit history.
- Do not disclose details learned from private repositories.
- Present repositories with only an initial commit as active explorations, not as
  completed products.

## Content structure

1. A concise introduction focused on backend systems, automation, and practical
   user-facing tools.
2. A "Recent work" section covering verified public activity since October 2025.
3. One detailed highlight for `beak_heamin_saipan`, including its interactive map,
   point-of-interest layers, photo popups, mobile-friendly interactions, and
   itinerary/transport guidance.
4. One grouped "exploring" item for `sports-event-scraper` and
   `sports-notification-service`, describing the intended scrape-to-notification
   pipeline without claiming unfinished implementation.
5. A compact skills section derived from the highlighted work and established
   public projects.
6. A condensed earlier-projects section linking to representative backend,
   algorithm, IoT, and desktop projects.
7. Existing contact links and GitHub statistics retained in cleaner Markdown.

## Editorial rules

- Use English to match the existing profile and repository audience.
- Prefer short, concrete statements over broad self-descriptions.
- Correct obvious grammar and spelling issues in retained content.
- Avoid unsupported proficiency levels, performance claims, and completion claims.
- Keep the README readable without relying on dynamically generated project cards.

## Verification

- Confirm all repository and contact links are syntactically valid.
- Confirm every recent project listed has activity on or after 2025-10-01.
- Confirm private repository names and details do not appear.
- Review the rendered Markdown structure for valid headings, lists, and image tags.
